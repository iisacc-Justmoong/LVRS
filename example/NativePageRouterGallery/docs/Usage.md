# 네이티브 페이지 예제

`Gallery.lvui`의 PageRouter는 C++ 백엔드가 소유한 컨트롤러를 받는다. `Home.lvui`,
`Report.lvui`는 각각 C++ 헤더로 AOT 생성되며, 페이지 팩토리가 생성 코드의 `build`
진입점을 호출한다. 콘텐츠 본문만 기존 빌더에 구성하므로 창이나 OS 컨트롤을
추가하지 않는다. 페이지마다 독립된 `PageBackend`와 바인딩 소유 스코프를 만든다.

툴바와 두 페이지 백엔드는 명시적인 공유 Navigator를 통해 활성 라우터로 명령을
보낸다. 실제 라우터는 NavigationTarget 인터페이스로 연결하며 창을 닫을 때 자동
등록 lease도 종료한다. 예제 self-test에는 이 전역 상태와 종료 후 등록 해제를 추가한다.

Home에는 텍스트 Link와 HStack 자식 콘텐츠를 가진 Link가 있다. href·replace·밑줄·
색상을 Core Observable에 연결한다. Target 43 버튼은 현재 Home 스코프의 href를
`/reports/43`으로 바꾸며 self-test는 생성한 Link를 통해 실제 대상이 바뀌는지 준비한다.
현재 Home 스코프 참조는 약하게 보관하여 페이지의 수명을 연장하지 않는다.

Navigator는 선택한 라우터의 논리 이력을 자신의 ViewStateTracker에 연결한다.
페이지 커밋 port는 별도의 PageMonitor에 방문 경로를 기록한다. 두 모델의 요약을
같은 LVUI 화면에 표시하며 Undo visit은 방문 로그만 되돌리고 실제 화면은 이동하지
않는다. 추적 목록의 loaded는 실제 비활성 페이지 캐시가 있다는 뜻이 아니다.

Home의 버튼을 통해 `/reports/42`로 이동하고 Report에서 뒤로 간다. 이전 화면은
즉시 종료되며 뒤로 가면 새 Home 스코프가 생긴다. 입력 필드의 편집 상태를 자동
저장하거나 비활성 페이지를 캐시하지 않는다. 장기 보존할 앱 데이터는 별도 모델에 둔다.

Core는 앱 진입점, UI 실행기, 작업자 결과와 프레임 루프, 종료 순서를 소유한다.
`--self-test`에는 페이지 생성·종료 5회, 탐색 알림, 백그라운드 결과, 크기 변경,
프레임 진행, 정상 종료 검사를 준비했다. 사용자 지시에 따라 현재는 코드 생성·
컴파일·링크와 설치 소비자 정적 검증만 수행하고 실제 실행은 마지막에 모은다.

`install.sh`는 예제 내부의 `build/`를 사용하고 기본 목적지는 `build/install`이다.
실행 검증을 자동으로 수행하지 않는다. 설치한 예제도 외부 LVRS 패키지를 찾아
독립적인 소비자로 다시 빌드할 수 있다.
