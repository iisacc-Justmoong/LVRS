# Modal 콘텐츠 로더의 활성화 수명 기반

원본 `Modal.qml`은 `contentComponent`를 열 때 로드하고 닫을 때 해제한다. 다시 열면 새로운
인스턴스를 만든다. 이 계약은 기존 Popover의 정적 콘텐츠 유지와 다르다. 우선 이를 위한
iiGUI의 독립 활성화 생성 경로를 구현했으며, 이제 [Modal](Modal.md)의 기본 조합과 LVUI 자식
코드 생성도 이 경로를 사용한다. 원본 전체 계약을 완료한 것은 아니다.

`Widget::set_popup_content(WidgetFactory)`를 비어 있는 Popover에 지정하면 열 때 한 루트 뷰를
만들고 닫을 때 소유권을 해제한다. `popup_content("picker.hex")`로 현재 활성화의 위젯을
얻으며 인자를 생략하면 루트이다. 닫힌 상태는 `closed` 결과이다. 정적 자식과 팩토리는
함께 사용할 수 없고 닫힌 유휴 상태에서만 팩토리를 교체한다.

```cpp
auto configured = popup.set_popup_content([](ii::gui::WidgetBuilder& builder)
        -> ii::core::Result<void> {
    auto picker = lvrs::ColorPicker::create(builder, {}, "picker");
    if (!picker) return std::unexpected(picker.error());
    return {};
});
```

실제 예제는 `examples/NativeActivationGallery`이다. 바깥 뷰와 부모 백엔드는 LVUI AOT와 Core
부착 수명을 사용하고, 콘텐츠는 컴파일한 C++ 팩토리가 만든다. 편집기 객체·모델·구독은
활성화마다 새로 만들고 닫으면 소유권을 해제한다. 부모 백엔드는 다시 만들지 않는다.
이 경로는 런타임 LVUI 소스 해석기나 VM을 넣지 않는다. `NativeModalGallery`에서는 LVUI
Modal 자식 문법이 직접 컴파일한 C++ 팩토리로 바뀌는 경로를 사용한다.

한 OS 창·입력 표면·GPU 표면에서 활성 콘텐츠를 합성한다. 콘텐츠마다 NSView·OS 컨트롤·
GPU 컨텍스트를 만들지 않는다. 포인터·텍스트·Tab·Escape·접근성은 활성 콘텐츠로 전달하고,
입력란의 포커스/IME와 중첩 메뉴의 창 경계 배치를 유지한다. 이전 핸들과 접근성 대상은
새 활성화를 조작하지 못한다. 내부 접근성 대상의 `@iiscope:` 표기는 파싱하지 않는다.

닫힘 알림 전에 콘텐츠의 소유 위젯·구독·참조를 해제하고 핸들을 닫는다. 이미 실행 중인
C++ 콜백이 가진 캡처는 반환까지 보호한 뒤 해제한다. 닫힘 알림만으로 모든 외부 공유 참조의
물리적 파괴가 끝났다고 가정하지 않는다. 임의 외부 작업을 추론해 취소하지 않으며,
콘텐츠가 소유한 Core TaskScope나 약한 수신자를 통해 작업 수명을 연결한다.

전체 활성 위젯 4096개·열린 팝업 8개·내장 활성화 깊이 8개를 제한한다. 실패한 팩토리는
부분 트리를 노출하지 않는다. 닫기·해제 중 생성은 차단하고 부모의 닫힘 콜백 이후 재개방을
허용한다. 500회 재개방, 실행 중 캡처, 닫힘 중 부모 제거와 오래된 접근성 대상도 검사한다.

예제에서는 적용한 색상은 부모 미리보기에 유지하고, 취소·외부 누름은 이전 기준색을 복원한다.
이 정책은 예제 소유자가 결정한다. 기본 Modal의 제목·설명·아이콘·최대 세 액션·중앙 배치·
폭에 따른 크기 계산도 구현했다. Modal은 정적 외곽을 유지하고 본문 Loader만 즉시 해제하며,
420ms/150ms 프레임 전환과 실행 중 모션 감소 설정도 사용한다. 원본 전체 컴포넌트의 모션·
속성 재바인딩·상속 계약은 계속 남아 있다.
