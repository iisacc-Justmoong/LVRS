# 계층 뷰의 네이티브 컨트롤러

`HierarchyController`는 기존 `HierarchyModel`과 독립적인 `HierarchyProjection`을
공유하여 선택·펼침·키보드 이동·드래그 미리보기를 C++에서 관리한다. 여러 컨트롤러가
같은 모델을 사용해도 활성 행과 펼침 상태는 독립적이다. 기존 QML은 비교 기준으로 보존한다.

`activate_by_key`/`activate_by_id`, 상대 이동과 좌우 이동은 보이는 활성 가능 행을
대상으로 한다. 기본값은 숨겨진 대상의 조상을 펼치는 것이다. 이를 끄면 숨겨진 대상은
활성화하지 않는다. 가지를 접어서 현재 선택을 가리면 접은 부모를 활성화한다. 선택과
펼침·높이·드래그 미리보기는 소스 모델 revision을 바꾸지 않는다.

모델 변경은 투영의 첫 번째 수신 단계 이후 컨트롤러의 두 번째 수신 단계에서 정규화한다.
투영의 읽기 전용 통지 안에서 재진입 쓰기를 하지 않으며 별도 이벤트 루프를 만들지 않는다.
두 단계 사이의 외부 조회는 `busy`이며 정규화한 상태만 발행한다. 모델 key가 유지되면
활성을 보존하고, 제거되거나 비활성화되면 초기 selected 행 또는 첫 활성 가능 행을 찾는다.

편집은 컨트롤러의 editable과 모델의 편집 가능 여부가 모두 참이어야 한다. begin/update
drag는 이동 계획만 보유하고 end_drag(true) 또는 명시적 move에서만 전체 하위 트리를
확정한다. 소스 revision이 바뀌면 오래된 미리보기를 취소한다. 이 모델은 표시용 모델이며
앱 파일에 영속 반영할 책임은 명시적 이동 이벤트를 받은 앱 백엔드에 있다.

Core Observable 의존성과 약한 QueryPort를 사용한다. 동일 활성화는 기본적으로 통지를
늘리지 않으며 force_signal로 명시적 재발행을 요청할 수 있다. 관찰 오류는 커밋을 취소하지
않고 다음 수신자도 호출한다. 소유 스레드·일반 재진입 변경·종료·소스 종료를 검사한다.

검사는 `tests/native/hierarchy_controller.cpp`에 준비한다. 저장소 지침에 따라 현재는
컴파일·링크·설치 소비자를 검증하며 실제 실행은 전체 목표의 마지막 일괄 단계에 남긴다.
이 컨트롤러 자체를 HierarchyItem/HierarchyList 전체 시각·상속·플랫폼 계약의 완료로
해석하지 않는다.

기본 행 높이 변경은 개별 높이 override를 보존하며 소스 revision을 바꾸지 않는다.
알림 중 end_drag(false) 요청은 현재 알림 뒤에 취소를 발행한다. 일반 변경과 이동 확정의
재진입은 계속 busy이며 위젯 종료 정리가 편집을 확정하는 경로가 되지 않는다.

수신자가 별도의 소스 모델을 갱신하면 현재 컨트롤러 알림 뒤에 정규화하여 후속 상태를
발행한다. 오래된 model_revision 때문에 컨트롤러가 계속 busy에 남지 않는다. 반복된
수신자-소스 순환은 최대 32단계로 제한한다.

`HierarchyControllerChange::expansions`는 실제 값이 바뀐 모든 행의 key·소스 index·
expanded 값을 보유한다. expand_all/collapse_all은 preorder 순서이며, 선택의 자동 조상
펼침은 원본 QML처럼 가까운 부모에서 루트로 진행한다. 이미 같은 값인 행은 기록하지 않는다.
한 명령의 최종 상태를 한 번 발행하며, 기존 key/expanded 필드는 마지막 펼침 변경을 남긴다.
동시 선택 변경은 state.active_key/id/index로 읽는다. 소스 정규화 중 발생한 조상 펼침도
같은 배치에 포함된다. 배치 index는 event.state.model_revision의 preorder를 가리킨다.
벌크와 자동 조상 펼침은 원본처럼 disabled 조상도 처리한다. 이는 해당 행을 선택하거나
클릭할 수 있게 만드는 것이 아니며, 개별 사용자 명령의 enabled 검사는 계속 적용한다.

생성 옵션 `initial_active_key`는 새 컨트롤러의 활성 키를 정규화 전에 지정한다. 기존 모델을
변경하지 않으며 해당 키가 없거나 활성화할 수 없으면 selected/첫 활성 가능 행으로 돌아간다.
이는 모델 소스 교체 시 선택을 이어받기 위한 초기값이며 지속적으로 선택을 강제하는 바인딩이 아니다.
위젯 목록은 모든 펼침 알림을 전달한 뒤 활성 알림을 전달하고, 한 콜백의 예외가 뒤의 콜백을
누락시키지 않도록 첫 오류를 마지막에 반환한다. 뷰가 퇴역하면 남은 알림을 중단한다.
전체 QML 신호·예약 갱신 시점과 플랫폼별 입력 동등성은 계속 남은 계약이다.
