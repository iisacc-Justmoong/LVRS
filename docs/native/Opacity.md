# 공통 opacity 입력과 네이티브 표시 트리

LVRS 네이티브 컴포넌트의 루트 위젯은 iiGUI의 `Widget::set_opacity`를 사용한다.
LVUI는 공통 입력 `opacity`를 같은 C++ 메서드에 연결하므로 컴포넌트의 선택색·disabled
색상을 변경하거나 개별 옵션에 opacity 필드를 중복 추가하지 않는다.

기본값은 1이며 유한한 0부터 1까지의 값만 허용한다. 작성한 값은
`WidgetSnapshot::opacity`, 일반 부모·소유 콘텐츠 부모의 곱은 `effective_opacity`에서
확인한다. 개별 paint 색상의 alpha와 애니메이션의 일시적인 진행률은 별도 값이다.

값을 바꾸어도 기존 컴포넌트의 루트·사용자 콘텐츠·입력·포커스·선택·파일 데이터는
유지한다. 0에서도 입력을 받는다. 비활성 정책은 enabled, 보임과 입력 제거 정책은
visible로 구분한다. 계층 행을 흐리게 표시하기 위한 시각적 투영이 원본 HierarchyModel의
revision이나 레이어 visible 필드를 변경해서는 안 된다.

표시 곱은 텍스트·이미지·패널·사용자 그리기·그림자·재질과 소유된 중첩 콘텐츠에
전달된다. 클립·투명도가 다른 형제의 배치도 구분한다. OS 창 자체의 투명도와 별도
오프스크린 그룹 합성은 이 계약에 포함하지 않는다.

`LVRSNativeOpacityTests`는 LVUI 공통 회귀 소스의 8개 사례와 네이티브 계층 행의 선택·
이름·count 변경 후 루트/슬롯 투명도 보존 1개를 컴파일한다.
모든 LVRS 앱·테스트·self-test 실행은 저장소 지침대로 전체 작업의 최종 일괄 단계에
모으므로 중간 컴파일·링크 성공을 LVRS 실행 또는 GPU 시각 동등성으로 보고하지 않는다.
이 작업만으로 원본 LVRS 전체 상속·이벤트·모션·플랫폼 계약을 complete로 바꾸지 않는다.
