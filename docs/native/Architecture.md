# LVRS 자체 위젯 구현

기존 LVRS 전체를 LVUI와 iiGUI로 옮기는 작업을 시작했다. 최종 목표는 기존 기능과 외형의 동등성이다.
현재 결과를 전체 이식 완료로 취급하지 않는다. [대응표](Parity.md)와 JSON 원장에 공개·내부 뷰,
수정자, 비시각 타입을 빠짐없이 유지한다.

## 구현 구조

- LVUI는 컴포넌트를 인스턴스화 가능한 C++23 위젯 클래스로 AOT 생성한다.
- `lvrs::Widgets`는 LVRS 컴포넌트 API이며 iiGUI의 C++ 위젯을 직접 생성한다.
- iiGUI가 위젯 트리, 레이아웃, 히트 테스트, 포인터 캡처, 포커스, 상태, 키보드와 텍스트 편집을 소유한다.
- 위젯의 패널·글자·아이콘은 iiGUI GPU 그리기 명령으로 렌더링한다. macOS에서는 Metal을 사용한다.
- Cocoa는 창, 단일 입력·표시 표면, 이벤트 변환, IME, 가상 접근성 객체를 제공한다.
- 버튼·레이블·레이아웃에 OS 컨트롤을 생성하지 않는다. 글자 조형·래스터화에 OS 글꼴 서비스를 사용하는 것은 위젯 래핑과 다르다.
- iiSDKCore가 `Application`, 작업자, 이벤트 루프, 진입점, 최종 실행 파일 및 리소스를 소유한다.

## 현재 사용 경로

기본 `LVRS_BACKEND=native`는 Qt를 찾지 않고 `LVRS::LVRS`를 빌드한다.
기존 QML 구현을 유지하는 호환 경로는 `LVRS_BACKEND=qt`로 명시한다.
이미 설치된 Qt 패키지와 기존 제품 설치본은 이번 작업에서 교체하지 않는다.

```cmake
find_package(LVRS CONFIG REQUIRED COMPONENTS Native)
lvui_generate(NAME MainView SOURCE MainView.lvui FRAMEWORK LVRS OUTPUT_VARIABLE generated)
iisdkcore_add_application(MyApp GUI SOURCES main.cpp "${generated}"
    LIBRARIES LVRS::LVRS RESOURCES ${LVRS_NATIVE_RESOURCES})
```

여러 설치본이 공존하면 `LVRS_DIR`을 네이티브 설치본의 `lib/cmake/LVRS`로 지정한다.
기존 환경의 `LVRS_ROOT`나 루트 패키지 진입점이 Qt 설치본을 먼저 선택할 수 있기 때문이다.
네이티브 설치에는 루트 전달 파일도 포함하여, 사용자가 같은 경로에 설치할 때 이전 플랫폼
전달 파일이 남아 다른 구현을 가리키지 않도록 한다. 설치 검증은 기본 경로를 바꾸지 않고
`build/` 아래 별도 경로에서 수행한다.

`examples/NativeGallery`는 이 경로를 실제 사용한다. PushButton·LabelButton의 다섯 톤,
IconButton·HelpButton·DropdownButton·IconMenuButton·LabelMenuButton, 필수 아이콘을 가진 Tab·TabBar,
ComboBox·Stepper·LabelSegmentedControl·IconSegmentedControl,
CheckBox·RadioButton·ToggleSwitch, InputField, Slider·ProgressBar,
VStack·HStack·ZStack·Spacer·Label과 창을 포함한다. 콜백은 원래 C++ 객체의
메서드로 컴파일되며 컴포넌트 문자열을 런타임에 해석하지 않는다.

12개 악센트의 기본·hover·pressed 값과 2% 창 혼합을 네이티브 Theme로 제공한다.
기본 값은 현재 QML 소스에서 옮겼으며 green은 `#00E71F`이다.

## 내장 아이콘과 탭

`Icons`는 원본 SVG 2,860개, Figma QRC 별칭, Theme 이름 정규화·별칭을 네이티브 데이터로
컴파일한다. 앱은 SVG 원본 폴더·Qt 리소스·QML 실행기를 요구하지 않는다. 원본 색상을
유지하고 비활성 아이콘에는 투명도를 적용한다. 공용 래스터 캐시는 128개·8 MiB 이내이며
스레드에서 같은 자산을 요청하면 동일한 불변 이미지를 공유한다.

실제 벡터 해석은 iiGUI의 고정 버전 네이티브 LunaSVG 코덱이 담당한다. 클리핑·마스크·
그라데이션·내장 데이터 이미지를 처리하며, SVG 필터를 포함하는 자산은 명시적 미지원 오류이다.
외부 파일 리소스와 암묵적 시스템 글꼴 검색은 비활성화한다. 전체 자산과 별칭을 실제로
래스터화하는 테스트가 누락과 해석 오류를 검사한다.

Tab의 레이블 왼쪽 아이콘은 필수이다. TabBar는 동일 너비의 정적 Tab 자식, 선택 인덱스,
비활성 탭 건너뛰기와 재선택, 키보드 포커스 이동·활성화를 자체 구현한다. 인덱스 변경
메서드는 콜백을 호출하지 않으며 사용자 선택만 `int` 콜백을 보낸다. 스크롤 정책·동적 모델·
전체 상속 속성·모션 계약은 남아 있다. DropdownButton은 표시와 클릭 동작을 제공하며
원본과 같이 메뉴 열기는 앱의 콜백이 담당하며, 갤러리는 아래의 자체 메뉴 API에 연결한다.

iiGUI는 레이어마다 텍스트·이미지 텍스처를 유지한다. 패널 색상만 바뀌는 호버는 글자와
아이콘을 다시 래스터화·업로드하지 않는다. 실제 캐시 작업 횟수와 텍스처 바이트를 제공하며
별도 오버레이 레이어는 아래의 글자·아이콘까지 덮을 수 있다. 레이어만으로 메뉴 행동이
구현되었다고 취급하지 않는다.

## 자체 메뉴와 팝업

[활성화 콘텐츠](ActivationContent.md)는 원본 Modal의 콘텐츠 로더를 위한 별도 수명 경로이다.
정적 Popover와 달리 열 때 만들고 닫으면 소유권을 해제하며, 동일 OS/GPU 표면을 유지한다.
이제 [Modal](Modal.md)의 중앙 배치·폭에 따른 헤더 높이·아이콘·최대 세 액션을 이 기반에서
조합한다. LVUI 자식은 컴파일된 생성 함수이고 부모 백엔드는 유지한다. 전체 모션·상속·
속성 재바인딩은 계속 남아 있다.

[Alert·AlertButton](Alert.md)은 원본의 1·2·3개 액션 기하와 메서드→클릭 순서를 제공한다.
Alert의 정적 노드는 닫아도 유지하며 부모 View에서 해제한다. 배경 콘텐츠만 캡처하는
실제 Metal GPU 흐림·반투명 tint·테두리를 사용하고 카드만 바뀌면 blur를 재사용한다.
그림자·스프링·일반 반응형 바인딩과 다른 재질 백엔드는 계속 구현해야 한다.

[ColorPickerButton](ColorPickerButton.md)은 원본 전용 색상환과 현재색을 그리는 자체 버튼이다.
공유 모델을 연결하면 같은 팝오버 편집 결과를 표시하며 열기 자체는 소유자 콜백이 담당한다.

일반 C++ 위젯 콘텐츠를 유지하는 [Popover](Popover.md)는 같은 오버레이 경로를 사용한다.
콘텐츠·모델을 재생성하지 않고 열기·닫기, 앵커 재배치, 모달/비모달 입력과 중첩 메뉴를 처리한다.

Menu·ContextMenu·MenuItem·ContextMenuItem·MenuDivider·ContextMenuDivider도 자체 C++ 노드로
생성한다. 팝업은 일반 레이아웃에서 제외하며 소유 세대와 소유 메뉴의 수명을 따른다.
원본 아이콘·방향별 화살표·선택/비활성 상태·단축키 슬롯과 일반 24 px/압축 18 px 행을
제공한다. 압축 레이블의 Inter Regular 12 px는 원본 TTF와 OFL을 Core 리소스로 부착한다.

화면 가장자리에서 방향을 바꾸고, 긴 메뉴는 스크롤한다. 키보드 이동은 비활성 항목과
구분선을 건너뛰며 포커스 행을 화면 안으로 옮긴다. 팝업 입력 포착, 바깥 클릭·컨텍스트 요청·
Escape·포커스 상실 닫기와 이전 포커스 복귀를 제공한다. 오른쪽 클릭 대상은 LVUI의
`targetId` 또는 C++ `set_context_menu`로 연결한다. 정적 문자열 `items`도 실제 항목 생성
코드로 펼친다. 명시적 항목 자식과 목록은 함께 지정할 수 없다.

일반 드롭다운, 압축 컨텍스트 메뉴, 소유 하위 팝업과 문자열 목록이 NativeGallery의 실제
동작 경로에 연결되어 있다. 액션·타입이 있는 인덱스 콜백·자동 닫기를 순서대로 수행하고,
콜백이 제거한 세대나 다시 연 팝업에 이전 활성화의 후속 처리를 적용하지 않는다.

메뉴는 불투명 재질 바탕과 12% 코팅, 별도의 클리핑된 행 레이어를 사용한다. GPU scissor가
패널·텍스트·아이콘을 함께 자르므로 스크롤 중 뒤쪽 글자가 메뉴 위로 올라오지 않는다.
클리핑만 바꾸는 갱신은 전경 텍스처를 다시 만들지 않는다. 원본의 64 px 배경 흐림·방사형
코팅·그레인·열림 모션, 동적 객체 모델·이름/payload 이벤트·전체 상속 API는 남아 있다.
현재 재질 바탕과 코팅은 명시적 대체 경로이며 원본 재질과 동등하다고 취급하지 않는다.

## 콤보 필드·스테퍼·세그먼트 행

`ComboBox`는 원본과 같은 97×20 클릭 필드이다. 기본·hover·pressed 표면은
panelBackground10·11·12이며, 레이블과 18×18 방향 표시를 자체 렌더링한다.
primary·borderless 톤, upDown·up·down 화살표, 텍스트·너비·활성 상태와 클릭/누름/해제/취소
콜백을 지원한다. 메뉴나 값 목록은 자동 생성하지 않는다.

`Stepper`는 18×18 크기이며 위·아래·양방향을 지원한다. 양방향은 포인터 해제 위치가
위 절반이면 `+1`, 아래 절반이면 `-1`을 보낸다. 숫자 값은 소유하지 않으며 앱이
`onStepped(int)` 결과를 적용한다. 위·아래 방향키와 가상 접근성 증가·감소도 같은 C++
경로를 사용한다. 단방향에서 반대 방향 요청은 무시한다. Enter·Space의 누름/해제와
포인터 동작은 `pressed → released → clicked → stepped` 순서로 처리한다.
포인터가 밖에서 해제되면 released만 보낸다. 비활성화·Escape·포커스 상실·다른 위젯으로
포커스 이동은 캡처를 취소한다. 해제 콜백이 트리를 제거하면 후속 클릭은 실행하지 않는다.
방향키는 키 입력마다 한 번 방출하며 자체 반복 타이머를 시작하지 않는다.

두 `SegmentedControl`은 원본처럼 독립 자식 버튼을 감싼 행이다. 자동 선택 그룹이나
currentIndex를 추가하지 않는다. label 행은 수평 4·수직 3.5, icon 행은 수평·수직 4,
간격 2, 테두리 2, 반경 12를 기본으로 한다. cylinder 모양과 borderless 톤 강제를
지원한다. 강제 옵션을 끄면 각 버튼의 명시적 톤을 유지한다. 정적 자식 View와 불투명
C++ 배경·테두리 색상만 지원하며, 반응형 스타일·동적 자식·반투명 테두리와 모션은 남아 있다.
스테퍼의 원본 흰색 SVG 글리프는 네이티브 자산 캐시를 공유하고 배경은 현재 악센트로 그린다.

## 검증과 남은 작업

갤러리의 `Frame` 표시는 200 ms 타이머 횟수가 아니라 Core의 공통 FrameLoop를 사용한다.
macOS의 표시 장치 동기 신호로 프레임을 진행하며 앱·게임에 같은 단계와 시간 계약을 제공한다.
화면의 숫자만 250 ms마다 표본 갱신하고, 실제 프레임 콜백은 표시 장치의 주기를 따른다.
고정 간격 시뮬레이션·일시정지·비배율 UI 갱신과 시간 예약 타이머는 각각의 의미를 유지한다.
표시 신호의 콜백률과 실제 GPU 장면 그리기·물리적 화면 표시 FPS는 서로 다른 지표이다.

갤러리 자체 검증은 고정 시간 대기로 프레임 도착을 추정하지 않는다. 작업자 결과·크기 변경
이벤트와 세 번째 실제 프레임을 모두 관측한 뒤 닫으며, 별도의 5초 watchdog은 누락한
조건과 관측한 크기·프레임 수를 포함한 오류를 반환한다.

`cmake --build build/native/build`, `ctest --test-dir build/native/build --output-on-failure`로
기준 소스 변경, 네이티브 경계, 팔레트, 실제 갤러리 실행을 검사한다.
iiGUI 테스트는 OS 컨트롤 부재, 실제 OS 이벤트 전달, 자체 입력 상태와 GPU 픽셀을 별도로 검사한다.

아직 전체 원본 속성·상태·동작, 모션과 재질, 메뉴·탭의 전체 계약·라우팅·표·계층·에디터,
SVG 필터와 다른 OS 입력 어댑터의 이식이 남아 있다. 입력란은 기본 UTF-8 편집과 IME
미리 편집·확정을 제공하지만 전체 선택·클립보드·검증기·replacement range 계약은 미완성이다.
원장의 `partial` 상태는 이 제한을 포함한다.

현재 일부 OS 접근성 클라이언트는 공용 값 설정 브리지 때문에 읽기 전용 가상 요소도
수정 가능하다고 표시한다. 실제 값 변경은 입력란에만 허용되며, 이 메타데이터 차이는
수정해야 할 항목으로 남겼다. 글리프·아이콘 아틀라스와 손상 영역 갱신을 포함한
대규모 화면 성능 동등성도 아직 검증·완료하지 않았다.

## 네이티브 색상 모델과 표면

`lvrs::ColorPickerModel`은 iiGUI의 C++23 모델을 같은 타입으로 제공한다. RGB·HSV·CMYK·알파·
그레이스케일·HEX와 원본 비교 색상·적용·취소를 처리하며 Core의 명시적 약한 변경 쿼리 수신자를
사용한다. 모델은 UI 소유 스레드에서 사용한다. 무채색의 마지막 색조, 검정 CMYK의 잠재 잉크,
알파 편집의 채널 보존은 원본 모델의 동작을 유지한다.

`Widgets::color_surface`와 LVUI의 `ColorPickerSurface`·`ColorField`는 같은 네이티브 객체를
사용한다. 여섯 표면이 모델 한 개를 공유할 수 있고 변경 알림으로 필요한 표면만 무효화한다.
배경 캐시는 휠/SV의 색조, HS의 밝기, 크기·배율을 기준으로 삼으며 선택점 이미지를 분리한다.
캐시에 배경이 없을 때 CPU에서 래스터화하고 기존 GPU 합성기로 표시한다. 절차적 GPU 셰이더나
대규모 아틀라스 구현을 의미하지 않는다.

원본 Figma 휠 PNG는 바이트를 바꾸지 않고 정적 라이브러리에 내장한다. 네이티브 자산 검사는
원본을 직접 디코딩한 전체 픽셀과 내장 결과를 비교한다. 이미 사용하던 PlutoVG/STB 코덱의
메모리 PNG 경로를 사용하며 새 외부 의존성·실행 시 소스 경로·OS 색상 패널은 추가하지 않는다.

전용 `examples/NativeColorGallery`는 여섯 색상 표면, HSV·알파 슬라이더, RGB·CMYK·그레이
편집, HEX 검증, 적용·취소, Core 작업자·프레임·크기 변경·정상 종료를 실제 C++ 객체로 구성한다.
추가한 `ColorPicker::create`와 `Widgets::color_picker`는 기존 위젯을 조합하여 여섯 편집 형태,
채널 입력·램프, 비교 체커보드·최근 색상, HEX·알파와 적용·취소·스포이트 요청을 제공한다.
원본 크기와 동작·수명 검사는 [합성 ColorPicker 계약](ColorPicker.md)에 기록한다.
`NativePickerGallery`는 그 합성을 LVUI로 생성한다. 정확한 전체 입력 스타일·재질·동작과
다른 플랫폼 입력 어댑터, 일반 C++ 멤버의 자동 재바인딩은 남아 있다. 단일 표면의 모델 교체는
명시적 `set_color_model`, 합성 선택기의 모델 포인터 교체는 다시 마운트하는 계약을 따른다.
