# 네이티브 렌더링 관측

RenderMonitor는 원본 속성 11개, invokable 5개와 setter 2개를 C++로 제공한다.
`attachWindow`는 iiGUI Host 또는 교체 가능한 PresentationSource를 받는다. 기본 객체는
비활성 상태이며 명시적인 start는 원본처럼 연결된 창이 없어도 활성 상태를 설정한다.
LVUI는 getter·명령을 연결하며 통계 계산이나 타이머를 실행하지 않는다.

## 관측 경계와 수명

원본 [frameSwapped](https://doc.qt.io/qt-6/qquickwindow.html#frameSwapped)는 프레임이
표시 대기열에 제출된 시점의 신호이다. 네이티브도 요청 수나 주기 타이머를 FPS로 간주하지
않으며 NativeCanvas의 실제 presentation 카운터 증가 후 정보를 발행한다. 이는 화면
scanout이나 GPU 실행 완료 측정값이 아니다. Host는 기존 Core 이벤트 루프로 전달하므로
렌더링 호출 안에서 LVUI를 다시 그리는 재귀를 만들지 않는다. 측정 시각은 제출 시점의
steady clock이며 콜백 대기 시간과 분리한다.

Host별 원천은 독립적이다. 자식 창은 실행 루프가 부모와 연결돼도 자기 원천과 종료를
유지한다. 창 종료는 대기 전달을 취소하고 종료 이벤트를 발행한다. 모니터는 기존 통계를
보존하면서 비활성화된다. 원천은 창 자원을 소유하지 않으며 모니터 퇴역은 관측만 제거한다.
다른 모니터나 파일 상태를 변경하지 않는다. 전달 큐가 포화되면 원천을 닫고 진단을 발행한다.
연속성이 깨진 외부 원천이나 역행 시각은 통계에 섞지 않고 lastError에 보고한다.

## 원본 수치 계약

기본 샘플 용량은 240개이고 범위는 16..2000개이다. 드롭 임계값은 기본 20ms이며
5..100ms로 제한한다. 첫 프레임은 시각 기준만 만들고, 양의 정수 밀리초 간격만 샘플에
넣는다. p95·p99는 양의 샘플 8개마다 최근 버퍼의 nearest-rank로 갱신한다. 용량 변경은
최근 순서를 보존하고 백분위를 즉시 계산한다. 스냅샷 필드 14개와 정수 종류도 원본과 대조한다.

드롭 수는 프레임 추가 시 누적된다. 임계값을 변경하면 최근 버퍼에서 다시 계산하지만,
용량 변경에서는 다시 계산하지 않는다. stop/start는 원본처럼 마지막 활성 시각을 유지해
재개 간격에 정지 시간을 포함한다. reset은 수치와 시각 기준을 비우고 연결·활성 설정을
유지한다. 비유한 임계값은 명시적으로 거부하는 네이티브 입력 제한이다.

상태 관측은 소유 스레드에서 수행하며 통지 중 재진입 명령을 거부한다. 이미 반영한 값을
관측 오류로 롤백하지 않는다. 새 캡처 결과가 도착해도 기존 뷰 노드를 갱신하며 파일 모델의
수정·저장 경로를 호출하지 않는다. 표시 자체가 새 프레임을 만들 수 있으므로 모니터 UI를
사용한 수치를 측정 오버헤드가 없는 값으로 해석하지 않는다.

## 검증

원본 두 파일 해시·클래스 API·초기 값·스냅샷 키는 native_render_contract.py로 대조한다.
이 감사는 Qt 실행 oracle이 아니다. 원천의 창 없는 검사는 iiGUI에서 실행하며, LVRS 모델과
실제 AOT 뷰 검사는 컴파일·링크 후 전체 목표의 최종 일괄 실행에 남긴다. 실제 창·GPU,
모든 OS와 원본 렌더 루프의 완전한 동등성은 별도 증거가 필요하다.
